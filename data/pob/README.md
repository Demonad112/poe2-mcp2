# data/pob — PoB2 data tables as JSON (generated)

Generated by `scripts/export_pob_data.py` from the PoB2 commit pinned in `src/pob/headless.py`
(`POB_COMMIT_PIN_FULL`). **Do not edit by hand.** Lua runs only at export time; consumers read JSON.

```bash
bash scripts/setup_headless_pob.sh                     # PoB2 checkout at the pin (once)
python scripts/export_pob_data.py                      # regenerate (needs `pip install lupa`)
python scripts/export_pob_data.py --check              # exit 1 if the committed JSON is stale
```

| File | Source | Notes |
|---|---|---|
| `constants.json` | `Data/Misc.lua`, `Modules/Data.lua` `data.misc` | monster tables are arrays: index = level − 1 |
| `bosses.json` | `Data/Bosses.lua`, `BossSkills.lua` | `bossStats` mirrors `Data.lua:871-876`; `bossMultipliers` from `data.misc` |
| `bases.json` | `Data/Bases/*.lua` | keyed by base name; `source_file` = Lua file stem |
| `gems.json` | `Data/Gems.lua` | keyed `gameId\|variantId`; `is_support`; `supports` index |
| `enums.json` | `Data/Global.lua` | `ModFlag`, `KeywordFlag`, `SkillType` |
| `modcache.json` | `Data/ModCache.lua` | text → `{mods, rest}`; mod tags under `tags` |
| `config_options.json` | `Modules/ConfigOptions.lua` | see below |

Encoding: Lua arrays → JSON arrays, other tables → objects (string keys); `math.huge` → `{"$inf": 1}`.

## config_options.json

Each `apply` is run against a recording ModList. `mods.player` / `mods.enemy` are lists of
`{op: add|replace, mod: {name,type,value,flags,keywordFlags,source,tags}}`.

* `"$val"` = the user's input; `{"$affine": [k, c]}` = `k*val + c`.
* `code: true` (+ `code_reasons`, `sample` at val=37) = not expressible as a template: output shape or
  non-affine dependence on input (`min(val,100)`, `if val > 0`), reads `build`, or parses mod text
  (`parsed_text` lists the lines to look up in `modcache.json`). Port these by hand.
* `list` rows: `by_value` is keyed by `json.dumps(val)`; `check` rows: one template for `true`.
* No `apply` → `reads_input: true`: calc code reads `input[var]` directly.
* `conditionEnemyExitedPresenceRecently` appears twice (rows 518/519); see `duplicate_vars` / `by_var`.
